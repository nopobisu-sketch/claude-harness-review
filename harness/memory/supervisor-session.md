기본 틀(메인=감독, 일회성은 Agent·맥락 이어 갈 일은 start_session)은 core-brief의 «Supervisor by default»가 정본이다. 일꾼 브리프의 이슈 번호는 hooks/agent-needs-issue.mjs, Agent의 model은 hooks/require-agent-model.mjs, 일꾼의 승인 창 거절은 hooks/deny-unattended-prompt.mjs, «머지·고칠까요» 류 질문은 hooks/no-ask-to-act.mjs가 지킨다. 아래는 그 밖의 운영 방식과 사용자 결정이다.

2026-11-12 사용자 지시(12일 세션 3): «이 세션은 지금 열려있는 모든 세션들을 감시하면서 놀고 있는 세션이나 다음에 해야 할 것을 두고 일을 안 하는 세션이 있으면 계속 푸시해서 일이 굴러가게 만들어. … 질문은 각 세션에 내가 들어가서 답할 테니, 병목이나 처지는 부분은 네가 확인해서 계속 진행하게 만들어. 어제는 내 답변을 8시간 기다리느라 업무 진행이 안 됐어. 나한테 알림을 띄워서 답할 수 있게 해 줘.»

**Why:** 11-11에 세션들이 사용자 답을 8시간 기다리며 멈춰 있었다. 사용자는 폰으로 여러 세션을 오가는데, 어느 세션이 무엇을 묻고 있는지 한눈에 볼 곳이 없었다.

**사용자가 «감독 세션»·«지휘자»·«coordinator»·«세션들 감시해»라고 하면(11-14부터 지휘자=감독):** 시작하자마자 아래 1번 감시를 켠다. 일꾼·검증 일꾼·묶음 게시판은 일이 생길 때 만든다.
1. **멈춤 감시는 이 한 벌뿐이다(11-13에 세 벌을 합침).**
   - 턴 끝남은 앱 공식 알림이 알린다(`start_session` 세션은 감독이 이어서 깨어나고, `Agent` 일꾼은 작업 알림). 지금 어떤지 한 번 보려면 `watch.sh status`.
   - 출력 없이 멈춤은 `~/claude-resume/supervisor/watch.sh`가 잡는다. 워크트리 세션과 그 아래 `Agent` 일꾼(`<세션>/subagents/agent-*.jsonl`, `meta.json`의 `finished`가 true면 뺌)의 전사 마지막 줄이 도구 호출이거나 응답을 기다리는 user 줄인데 8분(`STUCK_AFTER=480`) 넘게 안 바뀌면 «멈춤의심». 끝난 턴과 사용자가 끊은 턴은 보지 않는다.
   - 쓰는 법: `watch.sh wait <내 전사 id 앞 8자>`를 Bash `run_in_background`로 건다. 사건이 나면 출력하고 끝나므로 처리 뒤 다시 건다. 보고한 사건은 `seen.txt`에 남는다. 옛 멈춤을 받고 싶지 않으면 먼저 `watch.sh seed`.
   - 8분인 까닭: 정상 빌드·시험도 3~10분 걸린다. 11-11 사용자의 «3분 진척 없음» 지시(«3분 동안 진행 현황이 진척이 없으면 너가 다시 한번 수정하고 쳐줘.»)를 그대로 따르려면 `STUCK_AFTER=180 watch.sh wait …`. 멈춘 게 맞으면 사용자에게 묻지 않고 `SendMessage`로 고칠 방법을 넣고 필요하면 `stop_session`, 조치 뒤 한 줄로 알린다. 자식마다 따로 거는 루프는 쓰지 않는다.
   - 응답 없는 시작(11-09 함정: 자식이 지시를 받고도 첫 응답 없이 idle)은 이 감시가 «응답 없음»으로 잡고, 잡히면 같은 세션의 `Agent`(isolation: worktree, 백그라운드)로 넘긴다. 사용자가 연 세션의 승인 창, 끝나지 않는 명령도 이 감시로 잡는다.
2. 질문은 그 턴의 `wrap_up` 입력에 있는 `ask`·`blocked`에서 읽는다(전사 꼬리).
3. 깨어나면 전사 꼬리를 읽고 셋 중 하나로 처리한다.
   - **사용자만 답할 수 있는 질문**(제품 결정·시안·비용·사람 손): `PushNotification`으로 «어느 세션 · 무슨 질문»을 한 줄로. 같은 질문은 한 번만, 30분 뒤에도 답이 없으면 한 번 더.
   - **물을 필요가 없던 질문**(되돌리기 쉽고 상시 규칙으로 답이 정해진 것): «추천안대로 진행»을 보내되 감독의 판단이라고 밝히고 근거 규칙을 인용한다. **단, 다른 세션의 외부 쓰기(이슈 본문 수정·PR 댓글·운영 DB 등)는 이렇게 밀면 막힌다**(11-12: auto 모드가 «다른 세션의 승인만으로는 외부에 쓸 수 없다»며 막았고, 사용자 답을 따옴표로 인용해 전달해도 막혔다). 그래서 묻지 않고 하는 일은 브리프에 적어 일꾼이 하게 하고, 운영 DB 쓰기처럼 사용자 몫은 처음부터 알림으로 넘긴다. **사용자가 감독 세션에 직접 답한 외부 쓰기는 감독이 직접 한다.** 그 뒤 원래 세션에는 «감독이 처리했다»만 알린다.
   - **다음 단계를 말해 놓고 멈춘 세션:** 이어서 하라고 보낸다.
4. 일하는 중인 세션에는 메시지를 넣지 않는다(→ [[parallel-session-check]]). 폰·아이폰·운영 DB 같은 공유 자원 순서는 각 오케스트레이터가 잡으니 감독이 직접 건드리지 않는다.
5. 번호만 붙은 빈 세션에는 일을 넣지 않는다([[numbered-sessions-are-placeholders]]). keepalive 같은 예약 작업 세션은 감시 대상에서 빼고 정리 대상으로도 올리지 않는다.

## 11-12 사용자가 정한 운영 방식 («keepalive는 그대로 둬, 나머지는 추천대로»)

1. **창구는 감독 세션 하나.** 사용자는 감독 세션에만 말하고, 감독이 이슈로 만들어 일꾼(일회용 자식 세션, `start_session` user_asked)에 배정한다.
2. **쉬는 자리에는 큐에서 다음 이슈를 넣는다.** 동시에 도는 일꾼 수에는 상한이 없다(11-12 사용자: «동시에 2명 이상 해도 돼 10명 해도 되니까 상한 없애줘» — 처음 정한 «2개까지»를 없앴다). 착수할 수 있는 이슈는 바로 넣는다. 남는 제약은 둘뿐: 같은 파일을 건드리는 이슈는 차례로, 폰·시뮬레이터 같은 공유 자원은 한 번에 하나.
   - 일꾼을 띄우는 도구: 사용자 메시지로 시작된 턴에서는 `start_session`. 일꾼 보고·백그라운드 알림 턴에서는 Remote Control 중에 `start_session`이 거절되므로 `Agent`(general-purpose, `isolation: worktree`, 백그라운드). 11-14에는 폰(Remote Control) 메시지의 턴에서도 «이 턴은 그 세션을 열 수 없다»며 거절됐다. 거절되면 묻지 말고 곧바로 `Agent`로. 11-19에는 폰 메시지 턴에서 됐지만 프로젝트 밖 폴더를 `cwd`로 준 호출만 거절됐다 → 프로젝트 밖 작업장 일꾼은 `cwd` 없이 열고 브리프에 절대 경로. 에이전트 브리프에는 «최신 origin/main에서 새 브랜치»와 커밋·PR 끝줄을 적는다.
   - **`Agent` 일꾼은 감독 세션과 수명이 같다.** 11-19 코드 일꾼 셋이 감독 세션이 끝나면서 함께 죽어 커밋 안 한 작업이 사라졌다. 오래 걸리는 코드 일은 사용자 턴의 `start_session`으로 열고, `Agent`로 넣을 수밖에 없으면 브리프에 «뜻이 통하는 단위로 커밋하고 브랜치를 push». 세션을 다시 시작한 뒤에는 끊긴 일꾼의 작업 폴더·브랜치부터 본다.
   - 한도로 멈춘 에이전트를 재개할 때의 함정은 [[usage-limit-resume]].
3. **주차하고 다음 일로.** 일꾼 브리프에 «사용자 답이 필요하면 이슈에 질문을 번호 붙여 남기고, 그 답과 무관한 부분은 끝까지 한 뒤 턴을 끝낸다». 감독은 질문을 모아 알림을 보내고 빈 자리에 다음 이슈를 넣는다. 답이 오면 그 일을 맨 앞으로.
4. **CLAUDE.md의 «물어보라» 문장**은 고친 안을 먼저 보여 주고, 승인을 받으면 PR로 올린다.

머지가 끝난 일꾼의 세션·워크트리는 묻지 않고 정리한다(keepalive는 빼고). **하위 일꾼이 일하고 있는 세션은 보관하지 않는다(2026-11-19 사용자: «하위 일꾼이 일하고 있으면 앞으로 보관시키지 마. 맥락이 한번 끊어져서 업무 다시 시작할 때 엉킬 수 있으니까»).** 감독이든 일꾼 세션이든 그 세션이 띄운 `Agent` 하위 일꾼·백그라운드 작업이 돌면 끝날 때까지 둔다(턴이 끝나 쉬는 것처럼 보여도 돌고 있을 수 있다). 같은 날 감독 세션이 내려가며 하위 일꾼 셋이 커밋 없이 끊긴 것이 계기다. **보관 전에 `list_sessions`의 `cwd`와 `git worktree list`로 폴더를 함께 쓰는 세션이 없는지 본다**(11-14 `start_session`(worktree) 일꾼이 다른 세션의 폴더를 물려받은 적이 있다). 앱 설정 «PR이 닫히면 세션 자동 보관»이 켜져 있어(11-14 확인) 일꾼 PR을 머지하면 그 세션이 바로 보관된다. 다음 단계가 남은 세션은 머지 직후 `unarchive_session`과 `set_remote_control`로 되살린다.

조사 근거(11-12): 클라우드 세션은 저장소 권한 규칙을 읽지 않으므로 훅이 걸리는지 확인되기 전에는 옮기지 않는다.

## 11-13 사용자 지시 — 결정할 것은 감독 대화에 모아 알린다
«내가 결정해야할건 여기에 알려줘 내가 답변해줄게»(감독 세션 5). 사용자 답이 필요한 것은 감독 세션의 답변에 번호·a/b·추천을 붙여 한꺼번에 낸다. 폰 알림은 자리를 비운 동안의 보조 수단이다. 사용자가 이미 보류로 정한 이슈는 목록에 다시 올리지 않는다. (11-13 사용자 «답 기다리는 문단은 없애, 나한테 필요 없어» — 아티팩트 «질문 판»은 걷어냈고 되살리지 않는다.)

**11-14 덧붙임:** «내가 답해야할게 있다면 바로바로 알려줘». 사용자 답이 필요한 것이 생기면 모아 두지 말고 그 턴에 바로 번호·a/b·추천을 붙여 묻는다. 자리를 비웠을 수 있으면 `PushNotification`도 한 줄. 답이 필요 없는 진행 보고에는 알림을 보내지 않는다.

**11-14 감독 교대도 감독이 직접 연다:** 사용자 «새 감독도 너가 알아서 열어줄 수 있어? 메모리에 적어줘». 한 주제가 끝나 새 주제로 넘어갈 때 사용자에게 열어 달라고 하지 말고, 인수인계 메모를 최신으로 고친 뒤 `start_session`(user_asked, fresh, worktree, 모델은 아래 «감독 모델»)으로 새 감독을 연다. 브리프에는 «너는 감독이다, [[supervisor-session]]과 오늘 인수인계 메모부터 읽어라, 열린 일꾼 세션 id들»만. 새 감독의 첫 턴이 끝나면 Remote Control을 켠다([[remote-control-always-on]]). **함정:** 사용자가 폰 원격으로만 일하면 열 수 없다(user_asked는 «Remote Control 턴에서는 못 연다»로 거절, own_initiative 카드는 훅이 막음). 이때는 지금 감독이 계속 맡고 인수인계 메모를 최신으로 유지하며 «맥 앱에서 새 감독을 열어 달라» 한 줄만 알린다.
- **연 뒤 바로 `detach_session`으로 새 감독과 남은 일꾼 세션을 맨 위로 떼어 낸다**(11-14 사용자가 사이드바에서 새 감독이 옛 감독 밑에 매달린 것을 보고 물음). 떼어 내면 옛 감독을 보관해도 함께 보관되지 않고 턴 알림도 안 간다. 대신 떼어 낸 일꾼의 턴 알림은 누구에게도 안 가니, 새 감독은 `list_sessions`·`watch.sh`·이슈 댓글로 살피거나 일꾼마다 `SendMessage`(`notify_when_idle: true`, 메시지 없이)로 구독한다(`to`는 `ListAgents`의 세션 제목, 11-14 실측). 떼어 낸 뒤 옛 감독은 `watch.sh`를 끄고 사용자에게 한 줄 알린 다음 스스로 보관한다(`archive_session` "self"를 그 턴의 마지막 호출로. 11-14 사용자 «새 감독 만들면 너가 자동 보관하는걸로 해줘»). 보관 전 `list_sessions {"linked": true}`로 자식이 모두 떼어졌는지 확인.

## 11-14 swarm 방식 (사용자가 워크플로 페이지의 swarm 후보 넷을 «넷 다 실행»으로 고름)
- **역할 넷:** 지휘(감독) · 만드는 일꾼 · 검증 일꾼 · 감시(watch.sh, 토큰 0). 일꾼 쪽 절차는 프로젝트의 일꾼 브리프 문서에 있다.
- **검증 일꾼:** 판단 일의 일꾼이 «검증 대기»를 알리면 `Agent`(model opus, 백그라운드)로 띄운다. PR·이슈 번호와 브리프의 검증 절차만 준다(만든 쪽 대화를 넘기지 않는다). 일꾼 2~4명에 1명. 되돌림이면 PR 댓글 번호를 만든 일꾼에게 `SendMessage`로 전한다. 통과 기록이 붙었는데 만든 일꾼의 턴이 끝나 있으면 감독이 머지한다. 두 바퀴를 넘으면 일꾼이 이슈 질문으로 남긴다.
- **검증은 새 세션으로 열어도 된다(11-15 사용자 «일꾼 보고가 오면 검증 세션을 새로 열어도 된다»):** 일꾼 보고 턴에서도 묻지 않고 `start_session`(user_asked, fresh, worktree, Opus)을 먼저 시도한다. Remote Control 중에는 앱이 거절할 수 있다(11-15 실측, 이후 다섯 번 모두 거절). 거절되면 `Agent`로 넣고, 한 세션에서 한 번 거절되면 같은 종류의 턴에서는 다시 시도하지 않는다. 앱의 제약이니 사용자에게 다시 묻지 않는다.
- **팀 편성표:** 큰 일을 쪼갠 뒤 «일꾼 · 맡은 이슈 · 모델 · 검증 · 상태» 표(한 줄에 일꾼 하나, 다섯 칸 이하)를 한 번 보여 주고 묻지 않고 띄운다. 이후에는 바뀐 줄만. 세션 링크는 폰에서 안 열린다(11-11).
- **인수인계 메모:** 묶음별 상태는 스펙 이슈 댓글(묶음 게시판)에 두고, 메모에는 스펙 이슈 번호와 묶음 밖의 것(사람 몫·폰에 깔린 빌드·사용자 답 대기)만. **Why:** 11-13 하루에 감독이 두 번 교대했고 메모가 31KB·이슈 번호 78개까지 불어 새 감독이 필요 없는 묶음까지 통째로 읽었다.
- **감독 모델(11-15 사용자 «앞으로 fable 한도 확인해서 fable 한도 있으면 감독관은 fable로 만들어»):** 새 감독을 열기 직전에 `get_usage`로 «Weekly · Fable»(과 전체 주간)을 잰다. 100% 미만이면 Fable로 연다. `start_session`이 Fable을 거절하면 연 뒤 `set_session_model`, 그것도 안 되면 사용자에게 «앱 모델 메뉴에서 Fable로» 한 줄. Fable이 100%면 초기화까지 Opus.

## 무거운 자원만 차례 정하기 (11-17 사용자 결정)
일꾼을 여럿 띄울 때 전체 타임라인을 미리 짜지 않는다. 코드 작성은 전부 병렬로 두고, 겹치면 탈이 나는 자원(빌드·폰·시뮬레이터)만 한 번에 하나씩 차례로 쓴다.
**Why:** 프로젝트 E에서 11-17에 일꾼 여덟이 APK·아이폰 빌드를 함께 돌려 맥 부하가 380까지 올랐고, 같은 맥의 CI가 PR 넷에서 시간 초과로 거짓 실패했다. 사용자에게 a 타임라인 먼저 / b 그때그때 / c 무거운 자원만 차례를 물었고 c를 골랐다.
**How to apply:** 띄우기 전에 «빌드가 필요한 일»과 «코드만 쓰는 일»을 나눈다. 빌드가 필요한 일꾼의 브리프에 «다른 빌드가 돌고 있으면 기다렸다가 시작». 폰 확인은 PR마다 하지 않고 머지 뒤 빌드 하나로 묶는다. 빌드 잠금 훅이 생긴 프로젝트에서는 그 문장을 뺀다.
