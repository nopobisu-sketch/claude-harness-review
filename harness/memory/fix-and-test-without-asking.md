사용자 지시:
- 11-05: 작업 끝에 «남은 일은 사람이 폰에서 확인»이라고 적자 «너가 adb로 해줘», 이어서 «앞으로 너가 가능한 테스트는 자동으로 진행».
- 11-09: «문제가 있으면 계속 iterate 해서 될때까지 새 세션 만들어서 진행해, 나한테 물어보지 마» · «다 고친 다음에 내가 확인할게» · «내가 하는 일은 제품 결정하고 기획이야. 코드 최적화·버그 등은 어떤 버그인지 일단 고치고 나에게 보고해. 고친 다음 보고해 주면 내가 판단해서 되돌릴지 말지 정한다. 문제·버그·코드 최적화·보안 등 꼭 해결해야 하는 일 모두에 해당.»
- 11-19(프로젝트 E 작업): «다른 세션이랑 확인해서 이미 된 테스트는 나한테 물어보지 말아줘».

**Why:** 비개발자라 시험을 넘겨받아도 할 수 없거나 시간이 묶인다. 예: 프로젝트 E의 폰 시험에서 버그가 차례로 나왔을 때 «고칠까요?»를 물으니 사용자는 버튼만 누르는 왕복이 됐다. 사용자의 몫은 제품 결정과 기획이고, 고칠 일의 허락이 아니다. 시험은 묻지 않고 끝까지 한다는 일반 원칙은 전역 CLAUDE.md «안전 경계»가 정본이고, 진행 중 «고칠까요?»·머지 질문은 hooks/no-ask-to-act.mjs가 막는다.

**How to apply:**
- 버그·최적화·보안·성능은 고친 뒤 보고한다(이슈 하나 = PR 하나로 되돌리기 쉽게). 보고는 끝에 한 번: 무엇이 문제였고 어떻게 고쳤고 무엇을 확인했는지와 PR 링크([[main-session-is-orchestrator]]).
- 묻는 것은 제품 결정·기획·시안 승인·정책(ADR) 뒤집기·돈이 드는 일뿐이다.
- 사용자에게 손 확인을 부탁하기 전에 세 곳을 대조해 이미 된 시험은 묻지 않는다: 다른 세션 전사에서 사용자가 직접 한 말([[parallel-session-check]]의 jsonl 방법), 관련 이슈 댓글, 프로젝트 메모리의 인수인계 메모. 손 확인 목록은 한곳에만 두고 끝난 항목에는 근거(누가 언제 봤는지)를 적는다. 남은 항목은 «사람 손이 있어야 하는 것»과 «에이전트가 할 수 있는 것»으로 나눠 뒤쪽은 묻지 않는다.

프로젝트별 순서(프로젝트 E의 APK·adb 절차 등)는 각 프로젝트 메모리에 있다.
