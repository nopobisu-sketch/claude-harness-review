2026-11-19에 사용자가 «블렌더 MCP 쓸 때 종종 블렌더가 튕기는 것 같은데, 이런 일이 없도록 사전에 블렌더 쓸 때는 미리 그동안 블렌더 쓰면서 생겼던 이슈들을 조사해서 메모리로 적어놓는 활동도 같이 해주면 좋을 것 같다»고 요청했다. 이 파일은 그 조사 결과다(세션 기록·맥 충돌 보고서·MCP 확장 프로그램 소스·공개 이슈).

## 조사 결론

1. 기록에서 확인된 충돌은 전부 **화면 없이 돌린 Blender**(`Blender -b ...`)에서 났다. 맥 충돌 보고서 네 건은 모두 부모 프로세스가 `zsh`이고 책임 프로세스가 Claude 데스크톱이다. 화면이 있는 Blender나 MCP 때문에 튕긴 기록은 찾지 못했다.
2. Claude Code 세션 기록에 남은 MCP 도구 호출은 세 세션이고, 전부 «Cannot connect to Blender at localhost:9876»로 끝났다. 성공한 호출은 기록에서 찾지 못했다. 사용자가 느낀 «튕김»은 화면 없이 돌린 Blender가 죽을 때 맥이 띄우는 «Blender 예기치 않게 종료» 창일 가능성이 높다(추정). 11-13 세션 기록에 «Blender가 비정상 종료됐다는 창이 떴네요»라는 문장이 있다.
3. 가장 흔한 원인은 **Cycles Metal 렌더가 시작되는 1~2초 사이에 나는 충돌**이다(5건, 근본 원인은 확인하지 못함). 두 번째는 **출력을 `grep`으로만 걸러서 충돌을 못 알아챈 것**(5건 중 4건이 이 때문에 늦게 발견되거나 묻힘). 세 번째는 **환경 변수 이름 `TZ`**(1건, 확정).
4. 충돌은 그 실행 한 번만 잃는다. 화면 없이 돌린 Blender는 열어 둔 장면이 없으므로 파일이 깨진 사례는 없었다. 같은 명령을 다시 돌려 통과한 사례가 3건이다.

시각은 한국 시간이다. 원인 칸의 «확인»은 충돌 보고서나 기록으로 직접 본 것이고, «추정»은 정황만 있는 것이다. 새 문제가 생기면 맨 아래에 한 줄을 더한다.

## 원인 정리

**Metal 시작 충돌(5건, 근본 원인은 확인하지 못함).** 충돌 보고서 네 건에서 죽은 스레드의 맨 위가 모두 `ccl::ShaderCache::compile_thread_func` → `ccl::MetalKernelPipeline::compile` → `ccl::path_cache_get`이다. 세 건은 `___BUG_IN_CLIENT_OF_LIBMALLOC_POINTER_BEING_FREED_WAS_NOT_ALLOCATED`(할당되지 않은 포인터를 해제)이고, 11-19 16:44는 같은 자리에서 `NSURL fileURLWithPath:`가 예외를 던져 abort됐다. 네 건 모두 실행 후 1~2초, 첫 렌더 준비 중에 났다. 같은 순간 다른 스레드가 셰이더 원본 문자열을 만들고 있었다(`MetalDevice::preprocess_source`, `path_source_replace_includes_recursive`). 그래서 **한 프로세스 안에서 스레드끼리 부딪힌 것으로 추정한다.** 11-13 세션이 세운 «Blender 두 개가 동시에 셰이더 캐시를 건드렸다»는 가설은 11-13 한 건에서만 동시 실행이 확인되고 나머지에서는 확인하지 못했으므로, 필수 조건이라고 단정하지 않는다. 맥(MacBookPro18,1, macOS 26.5.1)과 Blender 5.2.1 LTS에서 났다. 같은 서명의 공식 이슈는 찾지 못했다.

**출력 필터가 충돌을 가림(재발 4건).** `Blender -b ... | grep -E "Traceback|Error"`는 SIGABRT 같은 충돌에서 아무 줄도 내지 않으므로 «오류 없음»처럼 보인다. 11-14와 11-19 16:09는 이 때문에 알아채지 못했거나 한참 뒤에 발견했다. 파이프의 종료 코드는 `grep`의 것이므로 Blender의 종료 코드도 사라진다.

**`TZ` 환경 변수(1건).** 시스템이 쓰는 이름의 환경 변수를 설정 값으로 쓰면 Blender가 시작하다 죽는다. 같은 입력이라 다시 돌려도 똑같이 죽는다(Metal 충돌과 다른 점).

**MCP 연결 실패(3개 세션).** Blender 본체가 떠 있지 않거나 애드온 서버가 켜져 있지 않을 때 나는 오류다. 이 맥에서 확인한 것: Blender 5.2 설정 폴더(`~/Library/Application Support/Blender/5.2/extensions/`)에 MCP 애드온이 없고, 설정 파일 `userpref.blend`의 마지막 저장이 11-03 14:52이며, 9876 포트를 듣는 프로세스가 없다. 애드온이 다른 위치에 설치돼 있을 가능성은 배제하지 못했다.

## 화면 없는 Blender는 전역 스크립트로 돌린다

`~/.claude/tools/blender-run.sh`를 쓴다(2026-11-19 사용자 «전부 추천대로»로 확정). 직접 `Blender -b`를 부르면 훅 `hooks/blender-run-guard.mjs`가 막는다: 11-19에는 «훅은 만들지 않는다»로 정했으나 11-25 사용자 «1235 반영해»로 뒤집었다(이슈 claude-harness#4). 잠금·로그 파일·`--expect` 출력 확인·3회 재시도·충돌 보고서 알림은 스크립트가 하고, 사용법은 스크립트 머리와 `blender-run.test.sh`에 있다.

```bash
~/.claude/tools/blender-run.sh --expect 출력1.png -- --factory-startup -P 스크립트.py
```

남은 약점: 훅은 Bash 도구의 명령만 본다. 셸 스크립트 파일 안에서 직접 부르는 `Blender -b`는 막지 못해 여전히 `grep` 함정에 걸린다.

## Blender를 쓰기 전에 확인할 것

1. 먼저 방식을 정한다. 오래 걸리는 일과 반복은 화면 없이(`-b`), 열려 있는 장면을 눈으로 보며 고치는 일만 MCP로 한다(아래 «구분» 표).
2. MCP를 부르기 전에 서버가 서 있는지 본다: `lsof -nP -iTCP:9876 -sTCP:LISTEN`. 비어 있으면 MCP를 부르지 말고 화면 없이 돌리거나, 사용자에게 Blender를 켜고 애드온 서버를 시작해 달라고 요청한다(사람 몫). 애드온이 «Allow Online Access»가 꺼져 있으면 서버가 조용히 시작되지 않는다(공식 저장소 이슈 #45).
3·4·8. blender-run.sh가 한다(한 번에 하나, 출력 파일 확인과 재시도, 충돌 보고서 알림). 직접 실행은 훅이 막는다.
5. 스크립트에 넘기는 환경 변수 이름은 `TZ`, `HOME`, `PATH`, `TMPDIR`, `LANG`, `USER` 같은 시스템 이름을 피하고 `BL_` 같은 접두사를 붙인다.
6. 화면 Blender에 쓰기 전에 사용자가 열어 둔 장면을 보호한다. 저장되지 않은 변경이 있으면 `bpy.ops.wm.save_as_mainfile(filepath=..., copy=True)`로 사본을 먼저 남긴다. 열린 장면을 비우는 호출(`read_homefile`, `read_factory_settings`)은 화면 Blender에서 쓰지 않는다(추론이며 공식 문서의 직접 경고는 아니다).
7. 스크립트는 `threading`을 쓰지 않는다. 편집 모드를 바꾼 뒤나 삭제·undo 뒤에는 이전에 잡아 둔 메시·객체 참조를 쓰지 않고 이름이나 인덱스로 다시 찾는다(Blender Python API 공식 문서: «Troubleshooting Errors & Crashes», «Python Threads are Not Supported»).

## MCP로 할 일과 화면 없이 돌릴 일

| 일 | 방식 | 근거 |
|---|---|---|
| 굽기(렌더) 전부, 여러 장 반복, 높은 샘플 | 화면 없이 `-b` | MCP 호출은 300초 안에 끝나야 한다(확장 프로그램 소스의 소켓 제한). 저장소 이슈 #70은 썸네일 렌더가 원래 해상도로 돌아 305초가 걸렸고 클라이언트가 약 3분 만에 포기해 서버를 사용 불가로 표시했다고 보고한다(Windows). |
| 파일을 새로 만들거나 설정을 초기화하는 작업 | 화면 없이 `-b --factory-startup` | 열려 있는 장면을 지우지 않는다. |
| 여러 세션이 동시에 일하는 작업 | 화면 없이 | MCP는 포트 하나(9876)를 모든 세션이 공유하므로 세션끼리 장면을 덮어쓸 수 있다(추론). |
| 열려 있는 장면 조회, 객체 요약, 화면 캡처, 작은 수정 | MCP | 사용자가 보는 장면을 그대로 읽는다. |
| 큰 스크린샷 | MCP는 조심 | 저장소 이슈 #21(macOS, v1.0.0)은 큰 캡처의 응답이 잘렸다고 보고했고 닫혔다. 1.0.3 이후 수정됐을 가능성이 있으나 확인하지 못했다. |
| `execute_blender_code_for_cli` 등 `_for_cli` 도구 | 가급적 직접 `-b`를 부른다 | 이 도구는 별도 Blender를 `--background`로 띄우며 `--factory-startup`을 붙이지 않아 사용자 설정과 애드온을 읽는다. 제한 시간이 120초이고 실행 파일을 PATH의 `blender`나 `BLENDER_PATH`에서 찾는다. 이 맥에서는 09-05 기록에 `blender not found`가 있어 PATH에 없을 가능성이 높다(시험하지 않음). 저장소 이슈 #72는 사용자 애드온이 켜져 있으면 프로세스가 끝나지 않고 멈춘다고 보고한다(Windows, 열려 있음). |

## 튕기기 쉬운 호출 모양과 대체

| 위험한 모양 | 대체 |
|---|---|
| `Blender -b ... \| grep ...`만으로 성공 판단 | `blender-run.sh --expect` 사용 |
| 반복문에서 Blender를 연달아 부르고 마지막에 한 번만 확인 | 실행마다 출력 파일을 확인 |
| 여러 세션이 각자 `Blender -b`를 직접 부름 | `blender-run.sh`(잠금이 차례를 지킴) |
| 환경 변수 이름 `TZ` 등 | `BL_` 접두사 |
| Python `threading`으로 `bpy` 호출 | 쓰지 않는다 |
| 삭제·모드 전환 뒤 이전 참조 재사용 | 이름·인덱스로 다시 찾기 |
| 화면 Blender에서 `bpy.ops.render.render`로 긴 렌더 | 화면 없이 돌리기 |

## 튕겼을 때 되살리는 순서

1. 화면 없이 돌린 Blender가 죽었으면 파일은 안전하다. 기대한 출력이 있는지 확인하고, 없으면 같은 명령을 다시 돌린다. 시작 1~2초 안에 죽었고 다시 돌려 통과하면 Metal 시작 충돌로 본다.
2. **같은 입력으로 두 번 연속 죽으면** 일시적 충돌이 아니다. 환경 변수와 스크립트를 의심한다(11-03의 `TZ` 사례). `$TMPDIR/blender.crash.txt`나 `~/Library/Logs/DiagnosticReports/Blender-*.ips`의 맨 위 스택을 읽는다.
3. 화면 Blender가 튕겼으면 사용자에게 알리고, Blender의 자동 저장 파일로 복구할 수 있는지 안내한다(공식 문서 «Crashes»). 이 맥의 자동 저장 위치는 확인하지 못했다. 이어서 연결 상태(2번 확인)를 다시 본다.
4. 어떤 경우든 그 자리에서 이 파일의 사례 표에 한 줄을 더한다.

## 작업을 잃지 않게 미리 해 둘 것

화면 Blender로 오래 다듬을 장면은 시작 전에 `.blend` 사본을 저장하고, 장면의 정본은 스크립트 파일에 둔다. 반복 굽기는 실행마다 출력 파일을 확인하고 보고 전에 빠진 파일이 없는지 센다.

**How to apply:** Blender를 쓰기 전에 «쓰기 전에 확인할 것»을 읽고, 일꾼 브리프에는 5번(환경 변수 이름)을 적는다(blender-run.sh 사용은 훅이 지킨다). 새 문제는 사례 표에 한 줄(날짜·증상·직전에 한 일·원인 «확인»/«추정»·푼 방법)을 더한다.

## 확인하지 못한 것

- 화면이 있는 Blender나 MCP 조작 중에 튕긴 사례(기록에 없음), Metal 시작 충돌의 근본 원인·공식 이슈(2021년 이슈 #94142의 우회 환경 변수 `CYCLES_METAL_DISABLE_BINARY_ARCHIVES=1`은 원문 미확인·미시험), 정확한 충돌 비율.
- MCP 애드온의 설치 위치(설정 폴더에 없음)와 `_for_cli` 도구가 이 맥에서 동작하는지.

**근거:** 공식 Blender Python API 문서·매뉴얼 «Crashes»(MCP 확장 프로그램에 번들), 확장 프로그램 1.0.1 소스(300초·120초 제한), Blender Lab `lab/blender_mcp` 이슈 #21·#28·#40·#45·#61·#70·#72·#73(11-19 공개 API로 읽음), 이 맥의 충돌 보고서 네 건·세션 기록.
