## 셸은 zsh다

Bash 도구는 사용자 프로필의 zsh로 돈다. bash 습관대로 쓰면 조용히 어긋난다.

- **배열은 1부터** — `${ARR[0]}`은 빈 값이고 첫 원소는 `${ARR[1]}`. 09-29에 이슈 10장을 `for i in 0..8`로 만들다가 첫 장이 «title can't be blank»로 실패하고 본문·번호가 전부 한 칸씩 밀려 다시 고쳐 넣었다. 여러 건을 만드는 스크립트는 번호를 한 줄씩 명시하거나 `for x in a b c` 목록을 쓴다. 굳이 배열이면 `bash -c '...'`로 감싼다.
- **heredoc은 `<<'EOF'`(따옴표)로** — 백틱 든 글(메모리·한글 본문 등)을 따옴표 없는 heredoc으로 쓰면 백틱 안 명령이 실행된다(09-18 실제로 `npx expo`·`npm ci`가 돌고 그 출력이 메모리 파일에 섞였다).
- **변수에 담은 명령은 낱말로 안 나뉜다** — `UI="python3 …"; $UI tap x`(폰 스모크), `U="python3 …"; $U tap`(Sentry 시험)이 실패하고, 그 뒤 줄은 그대로 돌아 엉뚱한 화면을 누른다. psql 호출을 담은 `$P`도 같다. 폰 단계는 변수 없이 쓰고 한 호출에 한 단계씩, 필요하면 함수나 얇은 스크립트로 감싼다.
- **`"$VAR:refs/heads/x"`는 `:r` 수정자로 먹힌다** → `${VAR}:refs/…` 또는 값을 그대로.
- **`echo ===`는 에러**다(zsh가 `=`로 시작하는 낱말을 명령 경로로 풀려 한다) — 구분선은 따옴표로 감싼다.

## 병렬 Bash 호출은 cwd를 공유한다 (09-18 #372 실측)

같은 응답에서 병렬로 보낸 Bash 호출들은 **cwd를 공유**한다. 한 호출이 `cd mobile && npx tsc`를 하면, `cd <워크트리 루트> && npx eslint mobile/...`처럼 앞에 cd를 붙인 이웃 호출도 `mobile/` 안에서 돌 수 있다 — eslint «No files matching the pattern», `npm run lint` «Missing script»가 그 증상이다. 하네스는 «작업 디렉터리는 호출 사이에 유지된다»고 하는데, 병렬 호출은 그 상태를 서로 경쟁하며 바꾼다.

**Why:** 에러가 첫 칸 하나만 나고 나머지는 «성공»처럼 보이거나, 증상이 내 코드 문제처럼 보여서(파일이 없다, 스크립트가 없다) 헤매기 쉽다.
**How to apply:** 하위 폴더에서 돌릴 명령은 **서브셸** `(cd mobile && npx tsc --noEmit)`로 감싸고, 루트로 돌아오는 `cd <루트> && pwd`를 단독 호출로 한 번 보낸 뒤 다음 배치를 이어 간다. «파일이 없다» 류 오류가 뜨면 코드를 의심하기 전에 `pwd`부터. 거짓 실패의 다른 자리는 프로젝트 메모리 «local-ci-gate-and-false-failures».

## 맥의 find는 `-newermt "-5 minutes"`를 못 읽는다 (2026-11-19 실측)

«최근 N분에 바뀐 파일»을 찾으려고 `find … -newermt "-30 minutes"`를 쓰면 맥(BSD find)에서는 오류 없이 **0건**이 나온다. 같은 폴더에 방금 만들어진 파일 186개가 있었는데 세 번 연속 0건으로 읽고, 정상으로 굽고 있던 일꾼을 «결과 없이 멈춤»으로 잘못 판단해 턴을 끊었다. 최근 파일은 `find … -mmin -30`으로 찾는다.

**Why:** 0건은 «없다»와 «찾는 방법이 틀렸다»를 구별해 주지 않는다.
**How to apply:** «없다»를 근거로 남의 작업을 끊거나 보고하기 전에, 있어야 하는 것이 확실한 대상(대조군)으로 같은 명령이 1건 이상을 내는지 먼저 본다. [[verification-lessons]]의 대조군 원칙과 같다.
