기본 틀(메인=감독, 이슈 하나=자식 하나, 일회성은 Agent·맥락 이어 갈 일은 start_session, 예외는 몇 번 도구로 끝나는 일)은 core-brief의 «Supervisor by default»가 정본이다. 이슈 번호는 hooks/agent-needs-issue.mjs, «새 세션은 묻지 말고 연다»는 hooks/no-ask-to-act.mjs, 자식의 승인 창 멈춤은 hooks/deny-unattended-prompt.mjs가 지킨다. 여기엔 브리프에 없는 것만 둔다.

2026-11-09 사용자 지시: «앞으로 내가 이슈를 주면 바로 시작하지 말고 항상 자식 세션을 만들어서 시작해. 내가 시작하는 메인 세션은 항상 오케스트레이션 세션.»

**Why:** 11-09 밤 세 세션이 서로 모른 채 같은 폰에 1분 간격으로 빌드를 덮어 깔아 서로의 시험을 망쳤다(프로젝트 E). 그 세 세션은 링크(start_session)로 만든 게 아니어서 결과 보고가 자동으로 오지 않았다.

- **공유 자원은 메인이 쥔다:** 실기기·시뮬레이터 설치와 시험, 운영 DB 손 쓰기. 자식 브리프에 «빌드 설치·기기 사용 금지, 머지 후 시험표를 메인에 보내라»를 넣는다. 머지가 다 모이면 메인이 한 번 깔고 시험을 몰아 돌린다.
- 자식은 PR 머지까지 스스로(merge commit). 판단 일은 CI 초록 뒤 «검증 대기»를 알리고 검증 일꾼의 통과 기록이 붙은 뒤 머지한다([[supervisor-session]] «11-14 swarm 방식»). 사용자 결정(시안 승인·grill)은 자식이 자기 wrap_up으로 묻고, 메인은 누구 답을 기다리는지 표로 추적한다.
- 같은 파일을 건드리는 이슈는 동시에 두 자식에 주지 않는다 — 순서로 나눈다.
- 시작 안 하는 자식(11-09 함정)과 멈춤 감시(3분 진척 없으면 묻지 말고 고쳐서 다시 돌린다, 11-11)는 [[supervisor-session]]의 감시 스크립트 절에 있다.

**11-11 사용자 지시 — 자식 세션의 질문은 메인이 보여 준다.** «앞으로 각 세션에서 물어보는 것들은 지휘자 너가 나한테 보여줘.» 자식이 사용자 답을 기다리면(보고 알림·`list_events`) 그 질문·선택지·추천을 번호 붙여 메인 답변에 그대로 옮겨 보여 준다. 시안 PNG도 메인이 받아 SendUserFile로 다시 보낸다. 사용자가 메인에서 답하면 메인이 SendMessage로 그 세션에 사용자 말을 따옴표로 전달한다. 사용자를 자식 세션으로 보내지 않는다. **Why:** 사용자는 폰(원격)으로 메인만 보는데, 답변 속 세션 링크(#local_…)는 폰에서 눌러도 안 열린다(11-11 확인).

**11-13 사용자 지시 — 감독 세션은 감독만 한다.** «너는 감독관이야 감독관역할만 해.» 13일 감독 세션이 시안(Blender 모델링·렌더·합성)을 두 시간 가까이 직접 만들었고, 일꾼 세션의 Blender와 동시에 돌아 충돌까지 냈다. 시안 제작·조사·설치처럼 도구를 여러 번 쓰는 일은 «의논해 보자»로 시작했더라도 일꾼 세션으로 넘기고, 감독은 브리프 쓰기·진행 확인·결과 검토·사용자에게 옮겨 보여 주기·답 전달만 한다. (이 문장의 범위 해석은 내 것이다: 사용자 말은 따옴표 안이 전부다.)
