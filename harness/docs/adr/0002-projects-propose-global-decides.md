# 프로젝트는 전역을 고치지 않고 건의만 한다

2026-11-25 사용자 결정. 프로젝트 세션은 전역 하네스(`~/.claude`의 규칙·메모리·훅·스킬·설정)를 고치지 않는다. 모든 프로젝트에 통할 것을 찾으면(규칙이든 도구 함정이든) 그 프로젝트 메모리 폴더의 `global-proposals.md`에 «건의»로 적는다. 전역(3일마다 도는 예약 작업, 또는 «건의 거둬»라는 말을 들은 전역 세션)이 `tools/harness-proposals.mjs`로 거둬 하네스 지도에 «프로젝트 건의 · 저장소 이름» 카드로 올리고, 사용자가 답칸에서 고른다. 프로젝트 세션의 전역 파일 쓰기는 `hooks/global-write-guard.mjs`가 막는다.

까닭: 사용자는 «전역은 제안만 해줘. 실행은 전역 제안 안건 보고 내가 골라서 진행할 예정. 그래야 이력 관리가 좋을 듯», «세부 프로젝트는 전역 수정 금지»라고 했다(프로젝트 I 세션, 11-25). 그 전에는 전역 규칙과 메모리 경로 훅이 프로젝트 세션에게 «범용 내용은 전역 메모리로 옮겨라»라고 안내했고, 프로젝트 I 세션은 그 안내대로 전역 메모리에 파일을 썼다가 이 결정을 듣고 되돌렸다.

## 고려한 다른 길

- **전역 저장소의 GitHub 이슈로 건의**: 이력은 가장 좋지만 이슈와 지도 두 곳의 상태를 맞춰야 해서 «지도 하나만 보고 파악»(0001)과 어긋난다.
- **프로젝트 세션이 지도에 카드를 바로 씀**: 바로 보이지만 지도 쓰기마다 승인 창이 떠서 폰에서 멈추고, 모든 프로젝트 세션이 카드 형식을 알아야 한다.
- **규칙·장치만 건의, 도구 함정 메모는 바로 전역에**: 함정이 곧바로 퍼지지만 «전역 수정 금지»에 예외가 생기고 경계를 세션이 판단해야 한다. 사용자는 전부 건의로 돌리기를 골랐다.

## 결과

- 도구 함정도 사용자가 고르기 전까지는 그 프로젝트 안에만 있다. 다른 프로젝트가 같은 함정을 만날 수 있는 대가를 받아들였다.
- 막는 훅은 Write·Edit 도구만 본다. 셸 명령으로 쓰는 길은 막지 못한다.
- 상태와 이력은 지도 카드 한 곳에 있다. 프로젝트의 건의 파일은 보낸 편지함이고, 상태 표기를 따로 맞추지 않아도 된다.
