# 하네스는 검토 묶음으로 보여 주고, 검토자는 따로 쓰는 설정 폴더에 깐다

2026-11-25 사용자와 그릴링으로 정했다. 검토자는 Claude Code를 쓰는 바깥 사람이다. 검토자는 하네스를 읽고 의견을 주며, 자기 환경에 깔아 돌려 보기도 한다.

## 정한 것

1. **보내는 것은 검토 묶음이다.** 원본 저장소(`claude-harness`)나 메모리를 그대로 넘기지 않는다. 전역 하네스(규칙·시작 요약·용어집·훅과 시험·도구·정리 스킬·결정 기록·전역 메모리)만 넣고, 프로젝트는 «프로젝트 A~K»처럼 이름을 가린 구조만 넣는다. 프로젝트 메모리와 대화 기록은 넣지 않는다.
2. **검토 묶음은 한 번만 만든다.** 처음에는 «도구가 매번 새로 뽑는다»로 정했으나, 사용자가 «이거 한번만 쓸거여서»라고 해서 바꿨다(같은 날). 일회용 스크립트로 한 번 뽑고, «결과물에 프로젝트 이름·별칭·사용자 경로·사용자 이름이 0건»은 그때 한 번 확인한다. 우리 하네스에는 도구를 남기지 않는다.
3. **검토 전용 비공개 저장소를 새로 만들어 검토자를 초대한다.** 원본 저장소의 이력(커밋 메시지의 프로젝트 이름)과 보관 폴더가 따라가지 않게 하려는 것이다. 개인 저장소에 초대하면 쓰기 권한까지 가지만, 검토 전용 저장소라 원본에는 닿지 않는다.
4. **검토자는 따로 쓰는 설정 폴더(`CLAUDE_CONFIG_DIR`)에 깐다.** 평소 `~/.claude`와 업무 세션을 건드리지 않는다. 그래서 묶음 안의 사본에서만 경로(공용 함수의 `~/.claude`, 훅 명령의 `$HOME/.claude/hooks`)를 «설정 폴더 변수가 있으면 그것, 없으면 `~/.claude`»로 바꾼다. 우리 하네스 자체는 고치지 않는다(한 번만 쓰므로).
5. **읽는 부분은 안내 문서(README)와 구조 그림(PNG)이다.** 그림은 이름을 가린 데이터로 하네스 지도를 굽는다. «특히 봐 주셨으면 하는 것»은 사용자가 나중에 채운다.
6. **스킬은 정리 스킬만 넣는다.** pstack(남이 만든 MIT 스킬의 사본)과 플러그인 16개, 커넥터는 이름·출처·판 목록으로만 적는다. 프로젝트 G 디자인 스킬은 프로젝트를 가리켜서 «프로젝트 G의 디자인 가이드 스킬»로만 적는다.
7. **settings.json에는 우리 장치(훅·금지 규칙)만 넣는다.** 모델, 켜 둔 플러그인, 출력 스타일, 화면 설정, 상태 줄, 환경 변수는 «설정 목록» 문서로 적는다.
8. **지도와 최신화 예약 작업은 읽기 자료로만 넣는다.** 묶음에는 우리 저장소의 끝내기 전 검사 스크립트(지도 검사 포함)를 넣지 않는다. 개인·프로젝트 예약 작업도 넣지 않는다.
9. **검토 의견은 사용자가 직접 전달한다.** 의견을 거두는 도구는 만들지 않는다.

## 고려한 다른 길

- **원본 저장소에 초대**: 가장 간단하지만 커밋 이력과 보관 폴더로 가린 이름이 다시 보인다.
- **지금 하네스 지도를 공유**: 살아 있는 화면이지만 저장소 카드에 프로젝트 이름과 상태가 그대로 보인다.
- **검토용 지도를 하나 더**: 이름은 가려지지만 «아티팩트는 하나로만»(0001)과 어긋나고 두 지도를 같이 맞춰야 한다.
- **검토자의 `~/.claude`에 덮어 깔기**: 고칠 것이 없지만 오늘 만든 훅이 검토자의 모든 세션(업무 포함)에 걸린다.

## 결과

- 우리 하네스는 여전히 «이 맥의 `~/.claude`에서 도는 것»이다. 다른 곳에서 돌리는 일은 묶음 사본에서만 풀었다.
- 검토 묶음은 만든 날의 모습이다. 다시 보낼 일이 생기면 그때 다시 만든다.
- 검토자 초대는 사용자가 검토자의 GitHub 아이디를 알려 주고 허락한 뒤에 한다.
