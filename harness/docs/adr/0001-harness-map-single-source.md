# 하네스 지도를 유일한 창구로 두고, 갱신은 장치로 강제한다

2026-11-23 · 그릴링 13문항에서 사용자가 정함.

전역 하네스가 실제로 모든 프로젝트에서 돌아가는지 사용자가 알 수 없었다. 전역 메모리는 목차만 자동으로 들어가서 하위 세션의 6%만 주제 파일을 열었고, 영상(vlfCjWuv4es)의 권장이 반영됐는지도 한눈에 볼 곳이 없었다. 그래서 아티팩트 «하네스 지도» 하나에 권장안·제안·전역 층·장치·저장소의 실측을 모으고, 옛 «프로젝트 E 워크플로»와 프로젝트 E용 예약 작업은 없앴다. 사용자는 이 지도 하나만 보고 실제 상황을 알고, 제안도 그 안의 답칸에서 고른다.

지도는 Claude 세션만 쓸 수 있으므로, «그때그때 반영된다»는 믿음은 장치로 만든다. 지도에 닿는 전역 파일을 바꾼 세션은 `~/.claude/.claude/stop-check.sh`가 지도를 다시 쓸 때까지 턴을 끝내지 못하게 막고, 3일마다 전역 예약 작업이 전부 다시 잰다. 실측이 3일을 넘으면 지도는 숨기지 않고 «오래됨»으로 드러낸다. 상태 값은 손으로 적지 않고 `tools/harness-measure.mjs`로만 잰다.

프로젝트마다 예약 작업을 두는 대신, 전역이 바뀌면 각 프로젝트의 다음 세션이 시작 요약의 «정리할 것»을 받아 전역 정리 스킬 한 벌로 맞춘다. 프로젝트마다 다른 점은 그 프로젝트 메모리 목차의 «전역과 다르게 하는 것»에만 적는다.

## 고려했던 것

- 화이트보드 유형: 바로 쓸 수 있었지만 검색·설명 칸·최근 바뀐 것이 없어 floorplan 같은 화면이 되지 않았다.
- floorplan 엔진을 그대로 쓰기: 모양은 같지만 답칸이 없어 제안을 고를 수 없었다.
- 프로젝트별 예약 작업·프로젝트별 정리 스킬: 새 저장소마다 새로 만들어야 하고 절차가 여러 벌로 중복된다.
- 권장안 상태를 날짜로만 흐리게: 오래돼도 맞는 권장안까지 흐려진다. 그래서 현행·시험·대체됨·버림으로 나누고 지도 색에는 현행만 센다.
